# 파일 선택 · SSH에서 bag 가져오기

개별 bag의 절대 경로를 매번 입력할 필요 없이 폴더에서 고른다.
로컬과 SSH 모두 최대 100개까지 선택할 수 있다. SSH는 현재 bag을 처리하는 동안 다음 파일 하나를
미리 받아 전송과 import를 겹친다. 여러 import 자체는 동시에 실행하지 않는다.
선택한 원본은 읽기만 하며, 일부 파일이 실패해도 다른 파일 처리를 계속한다.

## 로컬: 폴더에서 선택

1. 원본 데이터 아래 **📁 파일·폴더에서 선택…**을 누른다.
2. **허용된 폴더**에서 데이터 폴더를 고른다. 폴더 이름을 누르면 들어가고 **상위 폴더**로 돌아간다.
3. `.bag` 파일을 체크한다. **파일명 검색**, **표시된 파일 모두 선택**, **더 보기**도 사용할 수 있다.
4. **선택한 N개 사용**을 누른다. 왼쪽에 선택 목록이 표시되며 `×`로 개별 해제할 수 있다.
5. **원본 불러오기**를 눌러 처리한다. 선택만으로 작업이 시작되지는 않는다.
6. 작업 완료 후 **N개 원본을 현재 프로젝트에 추가**를 누른다. 하나라면 기존 버튼 이름을 쓴다.

LeRobot dataset은 폴더의 체크박스 또는 폴더 안의 **이 LeRobot 폴더 선택**을 사용한다.
직접 경로 입력도 유지한다. 입력란을 직접 수정하면 이전 여러 파일 선택은 해제된다.

웹에서 보이는 것은 **에디터 서버가 실행되는 PC의 파일**이다. 다른 PC의 브라우저에서 접속했다고
그 브라우저 PC의 파일이 자동으로 보이지는 않는다. 이 기능은 브라우저 파일 업로드가 아니다.
파일을 서버 PC로 옮기거나 SSH에서 불러오기를 사용한다.

### 데스크톱의 OS 파일 관리 창

상단 **Bag 선택…**은 OS 파일 선택창을 연다. `Ctrl`/`Shift`로 여러 bag을 고를 수 있다.
선택한 상위 폴더에만 접근을 추가 허용하고, **원본 불러오기**를 눌러야 작업을 시작한다.
LeRobot은 상단 **LeRobot 폴더 선택…**을 사용한다.

### 원하는 폴더가 목록에 없을 때

웹 탐색창은 workspace와 명시한 `--allow-root` 내부만 보여준다. 숨김 파일과 허용 범위 밖
심볼릭 링크는 표시하지 않는다. 서버 실행 시 데이터 폴더를 한 번 허용한다.

```bash
bash run.sh serve --workspace /data/editor-workspace --allow-root /data/robot-datasets
```

데스크톱에서는 상단 **Bag 선택…**으로 고르면 해당 폴더가 추가 허용된다.
OS 전체를 읽도록 `/`를 허용하는 대신 필요한 데이터 폴더만 허용한다.

## SSH: 원격 폴더에서 선택

**bag을 다운로드하지 않고 원격 PC에서 직접 편집**하려면
[SSH 원격 편집기 연결](REMOTE_EDITOR.md)을 사용한다. 노트북에서 `bash remote.sh`로 연다.
아래의 **SSH에서 불러오기**는 원격 bag을 편집기 서버로 다운로드하는 별도 기능이다.

### 처음 한 번 준비

- 편집기 PC에 OpenSSH client의 `ssh` 명령이 필요하다. Ubuntu OS 준비 스크립트에 포함된다.
- 원격 PC는 SSH 접속과 **Python 3**가 가능한 Linux/Unix 환경이어야 한다. ROS 실행이나 별도 에디터 설치는 필요 없다.
- 편집기를 실행하는 사용자 계정의 `~/.ssh/config`에 구체적인 `Host` 별칭이 있어야 한다.
  일반적인 `Include` 파일도 읽는다. `Host *` 같은 패턴은 선택 목록에 표시하지 않는다.
- **SSH 키 또는 ssh-agent**로 비대화식 인증이 가능해야 한다. 비밀번호 전용 로그인은 현재 앱에서 지원하지 않는다.

예시는 개인 SSH 설정에 본인의 값으로 작성한다. 이 설정 파일이나 키를 Git에 넣지 않는다.

```sshconfig
Host robot-up
    HostName <UP_PC_IP>
    User <SSH_USER>
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```

새 호스트라면 먼저 터미널에서 `ssh robot-up`을 실행하고 관리자가 제공한 호스트 키 지문을
확인한 뒤 등록한다. 키 암호가 있다면 ssh-agent에 로드하고 같은 환경에서 에디터를 실행한다.
앱은 호스트 키 확인을 생략하지 않고, 비밀번호/키 암호를 묻거나 저장하는 UI를 만들지 않는다.

연결 준비만 확인하는 예시:

```bash
ssh -o BatchMode=yes -o StrictHostKeyChecking=yes robot-up true
```

이미 다른 터미널에 SSH로 접속해 있다는 것만으로 앱의 비밀번호 인증이 자동 해결되지는 않는다.
GUI로 실행했을 때 agent가 보이지 않으면 키가 준비된 터미널에서 `bash desktop.sh`를 실행한다.

### 에디터 사용 순서

1. **SSH에서 불러오기…**를 누른다.
2. 기존 SSH 호스트를 고르고 **폴더 열기**를 누른다. 처음에는 원격 홈(`~`)을 연다.
3. 폴더를 눌러 이동하거나 데이터 폴더 경로를 한 번 입력한다. 개별 파일 경로를 입력할 필요는 없다.
4. 원격 `.bag`을 체크한다. 다른 폴더로 이동해도 같은 호스트의 선택은 유지된다.
5. **받은 bag 저장 폴더 → 폴더 선택…**에서 저장할 폴더를 고른다. **이 폴더에 저장**을 누르면 해당 workspace에 기억된다.
   경로를 직접 입력했다면 **이 경로 기억**, 원래 위치로 돌아가려면 **기본 위치**를 누른다.
   기본값은 `workspace/downloads`와 **자동 — rsync 우선**이다.
6. **선택한 N개 다운로드·가져오기**를 누른다.
7. 작업 목록에서 다운로드 MiB/전체 MiB·평균 MiB/s, SHA-256 검증, 가져오기 상태를 구분해 확인한다.
   다음 파일 다운로드와 현재 파일 import가 동시에 표시될 수 있다.
8. 완료된 원본을 **현재 프로젝트에 추가**한다. 진행 중에도 **준비된 원본 먼저 편집 (나머지 Import 계속)**이
   보이면 먼저 추가해 편집할 수 있다. 아직 처리 중인 원본은 완료 후 같은 버튼으로 추가한다.

### 브라우저에서 다운로드 저장 폴더 고르기

**SSH에서 불러오기… → 받은 bag 저장 폴더 → 폴더 선택… → 하위 폴더 클릭 → 이 폴더에 저장** 순서로 사용한다.
폴더만 표시하는 별도 창이므로 원격 bag 선택 목록은 그대로 유지된다. 검색·상위 폴더·더 보기를 지원한다.
선택 후 다음 다운로드부터 적용되며 다운로드를 시작하지 않아도 위치가 기억된다.

- 화면에 **저장되는 컴퓨터의 이름**과 기본 위치를 표시한다. 저장 대상은 **에디터 서버가 실행되는 PC**다.
  Up PC에서 서버를 실행하고 노트북에서 접속했다면 Up PC의 폴더를 고른다. 노트북의 OS 파일관리자를 여는 기능이 아니다.
- 위치를 바꿔도 기존 bag·부분 다운로드·annotation은 이동하지 않으며, 이미 실행 중인 작업은 시작할 때의 위치를 유지한다.
  이전 위치의 다운로드를 재사용/이어받으려면 그 위치를 다시 선택한다.
- 허용 폴더 목록에 SSD가 없으면 서버 실행 시 `--allow-root /media/USER/SSD/bags`를 추가한다.
  이미 존재하고 연결된 폴더를 선택한다. 웹 요청으로 새 접근 권한을 부여하거나 기존 파일을 옮기지 않는다.
- **기본 위치**는 현재 workspace의 `downloads`로 복원한다. workspace 자체나 import cache·Export 폴더는 바꾸지 않는다.

### 노트북 로컬 실행 + 외장 SSD

Up PC에 에디터를 띄울 필요는 없다. 노트북에서 `bash desktop.sh`를 실행하고,
앱 상단 **SSH 저장 폴더…**에서 연결된 SSD의 기존 폴더를 고른다. 이후 **SSH에서 불러오기…**의
저장 폴더를 확인하고 전송한다. 지정한 경로와 전송 방식은 해당 workspace에 저장된다.

- 받은 bag만 선택 폴더의 `<파일 식별자>/<원래 파일명>.bag`에 저장한다.
- 기존 annotation·프로젝트·import cache·기본 Export 결과 위치는 **기존 workspace 그대로**다.
  저장 폴더 변경이 기존 다운로드나 프로젝트를 이동시키지는 않는다.
- SSD를 작업 도중 빼지 않는다. 선택 폴더가 없어지거나 파일시스템 장치가 바뀌면
  시스템 디스크의 같은 경로에 새 폴더를 만들어 대신 받지 않는다. 다시 연결한 뒤 재시도한다.
  재연결로 장치 번호가 달라졌다면 저장 폴더를 다시 선택해 새 가져오기를 시작한다.
  같은 위치의 완료/부분 다운로드는 재사용할 수 있다.
- 모든 새 작업 데이터를 SSD에 저장하고 싶다면 노트북에서
  `bash desktop.sh --workspace /media/USER/SSD/kuavo-workspace`처럼 시작할 수 있다.
  새 workspace가 기존 annotation을 자동으로 옮기지는 않는다. 기존 절대 경로를 임의로 바꾸지 않는다.
- 노트북 브라우저 모드는 로컬 `serve`에 `--allow-root /media/USER/SSD/bags`를 주고 해당 폴더를 지정한다.
  HTTP 요청으로 접근 허용 범위를 임의로 넓히지 않는다.

### 자동 전송과 성능

**자동**은 로컬·원격 양쪽의 rsync가 3.1 이상이면 **rsync over SSH**, 없거나 구 버전이면
기존 **SSH 스트림**을 사용한다. 설치를 강제로 진행하거나 시스템/ROS 패키지를 업데이트하지 않는다.
각 PC에서 `rsync --version`으로 확인할 수 있다. **rsync over SSH**를 직접 선택한 경우
지원되지 않으면 이유를 표시하며 임의의 다른 방식으로 바꾸지 않는다.

rsync는 앱 전용 `download.partial`에만 이어 쓰며 완료 원본을 덮어쓰지 않는다.
`--append-verify`로 전송/기존 부분을 확인하고, 전송 후 로컬과 원격의 SHA-256을 별도로 비교한다.
검증 중에는 추가 읽기 시간이 들며, 이 시간은 다운로드 속도와 구분해서 표시한다.
검증 실패 파일은 `invalid-...partial`로 격리·보존하고 import하지 않는다.
원격 파일 크기/mtime이 바뀌어도 완료본으로 반영하지 않는다.

전송 연결은 기존 SSH 키·호스트 키 검증을 유지하고 SSH 압축을 끈다. 별도 HTTP/FTP 서버,
비암호화 rsync daemon, 새 포트 개방은 사용하지 않는다. 사용자의 암호화 알고리즘을 임의로 낮추지 않는다.
한 번에 다운로드 하나와 import 하나만 실행하며, 취소하면 진행 중인 미리받기도 함께 중단한다.
이미 완료한 다운로드/가져오기는 재사용할 수 있다.

실제 개선 폭은 네트워크·디스크·bag 압축·CPU에 따라 다르다. rsync도 SSH 연결이므로
Wi-Fi 자체의 속도 제한을 없애지는 않는다. 큰 파일은 유선 LAN과 SSD 연결을 우선 확인한다.
**가져오기/카메라 추출**이 오래 걸리는 것은 전송 속도와 다른 문제다.

녹화 중인 `.bag.active`는 표시하지 않는다. `.bag`이라도 전송 중 크기/수정 시각이 바뀌면
완료본으로 취급하지 않는다. 수집 종료 후 다시 선택한다. 현재 SSH 기능은 **bag 파일용**이며,
원격 LeRobot 폴더 전체를 내려받는 기능은 포함하지 않는다.

## 중단·실패 후 이어가기

작업의 **작업 취소**는 다음 전송/처리 단위에서 반영된다. 이미 완료된 원본과 미완료
다운로드를 지우지 않는다. 앱 창만 닫는 것은 취소가 아니며 worker는 계속 실행된다.

실패 또는 취소된 여러 파일 작업에서 **중단·실패한 파일 이어가기**를 누르면:

- 이미 import가 끝난 원본은 건너뛴다. 해당 원본은 이전 작업의 추가 버튼을 사용한다.
- 다운로드 중이던 파일은 남은 `.partial`에서 이어받는다. 기존 부분의 SHA-256을 원격과 비교한다.
- 다운로드가 끝난 파일은 로컬 cache를 재사용한다. 완료된 전체 파일을 다시 전송하지 않는다.
- 새 작업으로 나머지를 처리하므로 이전 작업의 결과/로그는 남아 있다.

완료 작업에서 같은 파일을 다시 선택하면 다운로드뿐 아니라 정상 Import 캐시도 재사용한다.
프로젝트에 등록하는 원본 ID는 새로 부여할 수 있으므로, 이미 등록한 원본을 중복 추가하지 않도록 확인한다.
기존 source ID의 annotation이나 다른 프로젝트의 라벨은 자동 복사·변경하지 않는다.

## Import 처리와 캐시 재사용

### 빨리 편집을 시작하는 방법

1. 여러 bag을 선택해 Import를 시작한다.
2. 작업 목록에 **준비된 원본 먼저 편집 (나머지 Import 계속)**이 나타나면 누른다.
3. 완료된 bag의 영상·수치 데이터로 annotation을 시작한다. 나머지 Import는 계속된다.
4. 추가 bag이 준비되면 같은 버튼으로 추가한다. 먼저 편집한 annotation은 그대로 유지한다.

한 bag 안에서도 준비가 덜 된 프레임을 완성된 것처럼 공개하지는 않는다. 첫 bag은 인덱스를 읽고
카메라·수치 배열 준비를 완료해야 하며, 최초 Import가 즉시 열리는 방식은 아니다.
대신 편집에 불필요한 TF·VR 이벤트 JSON 변환을 기다리지 않고, 배치 전체 완료도 기다리지 않는다.

### 저장 방식

- 새 캐시: `workspace/import-cache/<식별자>-<세대>/`의 `camera_0.frames` 등.
  원본 JPEG/PNG 바이트를 순서대로 저장하고 catalog가 프레임의 위치·길이를 가리킨다.
  raw RGB만 기존처럼 무손실 PNG로 변환한다. 영상 프레임을 버리거나 JPEG를 재압축하지 않는다.
- 관절·명령 값과 validity mask는 계속 `.npy`, 시간 매핑은 `.npz`로 저장한다.
- 진행 상태는 작은 `jobs/<작업>/status.json`, 전체 작업 결과는 `result.json`으로 나눈다.
  이미지 목록은 catalog에만 두며 작업 목록이 매번 전체 과거 Export 요청을 다시 해석하지 않는다.
- 이미 만들어진 개별 이미지·JSONL/gzip 이벤트 캐시는 변환하거나 지우지 않고 그대로 지원한다.

### 재사용 조건

원본의 절대 경로, 파일명·크기·수정 시각 기반 fingerprint, 전체 Import profile,
Import 형식 버전을 확인한다. 새 캐시는 완료 receipt와 배열·묶음 파일의 메타데이터를 확인하고,
이전 버전 캐시는 배열·시간 매핑·모든 참조 이미지의 존재와 비어 있지 않음을 확인한 뒤 채택한다.
size/mtime fingerprint는 파일 내용 전체의 암호학적 체크섬이 아니다. 외부에서 내용을 수정하고
파일 크기·수정 시각까지 복원한 변경이나 모든 JPEG 내부 손상까지 검출한다는 의미는 아니다.

캐시가 누락·불완전하거나 설정/버전이 다르면 새 세대로 준비한다. 기존 세대나 annotation을
덮어쓰거나 자동 삭제하지 않는다. 같은 bag을 동시에 요청하면 하나가 준비하고 다른 작업은 기다린다.
이 재사용 범위는 **같은 workspace**다. 서로 다른 workspace의 캐시를 자동 합치지는 않는다.

### TF·VR 이벤트와 원본 bag 보관

새 Import는 이벤트 전체를 JSON으로 복제하지 않는다. 원본 bag에 전체 메시지를 그대로 보존하고,
Export 때 선택 구간의 이벤트를 JSON provenance로 만든다. **원본 bag 경로가 계속 필요하다.**
이벤트 처리 비용이 사라지는 것이 아니라 Import에서 Export로 옮겨지며, Export 시 원본을
추가로 읽을 수 있다. 과거 이벤트 JSON이 있는 캐시는 기존처럼 해당 파일을 사용한다.

랙 기준 base pose 역산은 이 선택 구간 제한과 별개다. 기존 whole-body 경로는 계속
**전체 녹화의 TF·odom·마커 관측**에서 기준을 잡아 선택 프레임을 계산한다.
구간 밖의 좋은 관측을 버리거나 TF를 다운샘플링하지 않는다.

### 기존 서버 업데이트

새 코드는 이전 캐시를 읽지만, 이전 코드는 새 `.frames` 캐시를 읽지 못한다.
**같은 workspace를 사용하는 서버와 worker는 동일한 버전으로 맞춘다.** 실행 중인 구버전 서버에
파일만 덮어쓰면 새 worker와 구 서버가 섞일 수 있다. 별도 폴더에 업데이트를 준비하고,
작업이 끝나고 브라우저 편집을 저장한 뒤 서버를 종료해 새 버전으로 다시 시작한다.
기존 Import/Export를 임의 중단하거나 다른 작업자의 서버를 재시작하지 않는다.

### 원격 브라우저의 영상 갱신

재생 중에는 최대 640×360의 경량 JPEG 미리보기를 사용하고, 정지하면 최대 960×540의 선명한
프레임으로 다시 요청한다. 원본·annotation의 프레임 번호·LeRobot Export 화질은 바꾸지 않는다.
이미 크기·용량이 적절한 JPEG는 다시 인코딩하지 않는다. 반복 조회한 미리보기는 RAM에만
최대 64 MiB/512장까지 보관하며 디스크 캐시나 새 MP4를 만들지 않는다.

Torso·그리퍼 원본 조회에 쓰는 bag 인덱스도 파일 identity가 같으면 RAM에서 재사용한다.
각 조회는 독립 파일 핸들을 쓰고 MD5 확인은 유지한다. 시간 조회는 인덱스를 이진 탐색해
앞부분 메시지를 매번 훑지 않는다. 인덱스 캐시는 최대 2개 bag, 기본 약 256 MiB 예산이며
활성 reader 자체의 메모리는 별도다. 메모리가 작은 PC에서는 서버 실행 시
`EDITOR_BAG_INDEX_CACHE_MB=64`로 줄이거나 `0`으로 끌 수 있다.

최초 bag 인덱스 로딩과 네트워크 대역폭/지연은 여전히 영향을 준다. 원격 3개 카메라를 항상
30 FPS로 전달한다고 보장하지는 않는다. 데이터 프레임을 버리는 것이 아니라 재생 미리보기만
현재 재생 시각을 따라가며, 정지·프레임 이동에서는 지정한 프레임을 확인한다.

## 저장 위치·원본 보존·제한

- 받은 bag: `workspace/downloads/<파일 버전 식별자>/<원래파일명>.bag`
  (사용자 지정 시 선택한 저장 폴더 아래에 같은 구조로 저장).
- 미완료: 같은 폴더의 `download.partial`; 완료 시에만 `.bag`으로 반영한다.
- 전송 검증: SHA-256으로 이어받은 부분과 완료 파일을 확인한다.
- 버전 구분: Host 별칭·원격 절대 경로·크기·mtime으로 cache를 구분하므로, 새 버전이 기존 프로젝트 원본을 덮어쓰지 않는다.
- 빠른 재사용은 원격 size/mtime 및 로컬 size/mtime 기록으로 판정한다. 외부에서 내용을 바꾼 뒤
  크기/mtime까지 원래대로 복원한 변경은 감지하지 못한다. cache 파일은 직접 수정하지 않는다.
- 원격에는 폴더 조회·stat·파일 읽기만 수행한다. 원격 원본의 수정·삭제·이동 명령은 없다.
- SSH 비밀번호·개인 키·SSH 설정 내용은 프로젝트/Git에 저장하지 않는다. 작업/다운로드 기록에는
  재시도에 필요한 Host 별칭과 원격 경로가 남으므로 workspace는 개인 작업 데이터로 관리한다.
- import cache와 다운로드 원본이 모두 필요해 로컬 디스크 사용량이 늘어난다. 자동 삭제하지 않는다.
- 강제 종료로 lock이 남았으면 PID와 작업 상태를 확인한 후 복구한다. 실행 중인 작업의 lock을 지우지 않는다.
- 에디터 API는 SSH 접근 기능도 있으므로 인증 없이 외부 IP에 공개하지 않는다. 원격 UI 접속은 SSH 터널을 쓴다.

검증은 합성 bag, 로컬 read-only helper와 실제 rsync 송수신 프로토콜로 수행한다.
부분 파일 재개·잘못된 prefix 재검증·취소 후 재개·특수문자 파일명·다음 파일 미리받기를 확인한다.
실제 robot-up 같은 개인 호스트의 키 인증·네트워크 속도는 사용 환경에서 확인해야 한다.

공식 참고: [OpenSSH ssh](https://man.openbsd.org/ssh.1), [SSH 설정](https://man.openbsd.org/ssh_config.5),
[rsync 전송·부분 파일 검증](https://download.samba.org/pub/rsync/rsync.1).
