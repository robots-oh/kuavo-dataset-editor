# 파일 선택 · SSH에서 bag 가져오기

개별 bag의 절대 경로를 매번 입력할 필요 없이 폴더에서 고른다.
로컬과 SSH 모두 최대 100개까지 선택할 수 있고, 여러 파일은 한 작업에서 차례로 처리한다.
선택한 원본은 읽기만 하며, 일부 파일이 실패해도 다른 파일 처리를 계속한다.

## 로컬: 폴더에서 선택

1. 원본 데이터 아래 **📁 파일·폴더에서 선택…**을 누른다.
2. **허용된 폴더**에서 데이터 폴더를 고른다. 폴더 이름을 누르면 들어가고 **상위 폴더**로 돌아간다.
3. `.bag` 파일을 체크한다. **파일명 검색**, **표시된 파일 모두 선택**, **더 보기**도 사용할 수 있다.
4. **선택한 N개 사용**을 누른다. 왼쪽에 선택 목록이 표시되며 `×`로 개별 해제할 수 있다.
5. **원본 불러오기**를 눌러 처리한다. 선택만으로 작업이 시작되지는 않는다.
6. 작업 완료 후 **N개 원본을 현재 프로젝트에 추가**를 누른다. 하나라면 기존 버튼 이름을 쓴다.

LeRobot dataset은 폴더의 체크박스 또는 폴더 안의 **이 LeRobot 폴더 선택**을 사용한다.
직접 경로 입력도 유지한다. 입력란을 직접 수정하면 이전 여러 파일 선택은 해제된다.

웹에서 보이는 것은 **에디터 서버가 실행되는 PC의 파일**이다. 다른 PC의 브라우저에서 접속했다고
그 브라우저 PC의 파일이 자동으로 보이지는 않는다. 이 기능은 브라우저 파일 업로드가 아니다.
파일을 서버 PC로 옮기거나 SSH에서 불러오기를 사용한다.

### 데스크톱의 OS 파일 관리 창

상단 **Bag 선택…**은 OS 파일 선택창을 연다. `Ctrl`/`Shift`로 여러 bag을 고를 수 있다.
선택한 상위 폴더에만 접근을 추가 허용하고, **원본 불러오기**를 눌러야 작업을 시작한다.
LeRobot은 상단 **LeRobot 폴더 선택…**을 사용한다.

### 원하는 폴더가 목록에 없을 때

웹 탐색창은 workspace와 명시한 `--allow-root` 내부만 보여준다. 숨김 파일과 허용 범위 밖
심볼릭 링크는 표시하지 않는다. 서버 실행 시 데이터 폴더를 한 번 허용한다.

```bash
bash run.sh serve --workspace /data/editor-workspace --allow-root /data/robot-datasets
```

데스크톱에서는 상단 **Bag 선택…**으로 고르면 해당 폴더가 추가 허용된다.
OS 전체를 읽도록 `/`를 허용하는 대신 필요한 데이터 폴더만 허용한다.

## SSH: 원격 폴더에서 선택

### 처음 한 번 준비

- 편집기 PC에 OpenSSH client의 `ssh` 명령이 필요하다. Ubuntu OS 준비 스크립트에 포함된다.
- 원격 PC는 SSH 접속과 **Python 3**가 가능한 Linux/Unix 환경이어야 한다. ROS 실행이나 별도 에디터 설치는 필요 없다.
- 편집기를 실행하는 사용자 계정의 `~/.ssh/config`에 구체적인 `Host` 별칭이 있어야 한다.
  일반적인 `Include` 파일도 읽는다. `Host *` 같은 패턴은 선택 목록에 표시하지 않는다.
- **SSH 키 또는 ssh-agent**로 비대화식 인증이 가능해야 한다. 비밀번호 전용 로그인은 현재 앱에서 지원하지 않는다.

예시는 개인 SSH 설정에 본인의 값으로 작성한다. 이 설정 파일이나 키를 Git에 넣지 않는다.

```sshconfig
Host robot-up
    HostName <UP_PC_IP>
    User <SSH_USER>
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```

새 호스트라면 먼저 터미널에서 `ssh robot-up`을 실행하고 관리자가 제공한 호스트 키 지문을
확인한 뒤 등록한다. 키 암호가 있다면 ssh-agent에 로드하고 같은 환경에서 에디터를 실행한다.
앱은 호스트 키 확인을 생략하지 않고, 비밀번호/키 암호를 묻거나 저장하는 UI를 만들지 않는다.

연결 준비만 확인하는 예시:

```bash
ssh -o BatchMode=yes -o StrictHostKeyChecking=yes robot-up true
```

이미 다른 터미널에 SSH로 접속해 있다는 것만으로 앱의 비밀번호 인증이 자동 해결되지는 않는다.
GUI로 실행했을 때 agent가 보이지 않으면 키가 준비된 터미널에서 `bash desktop.sh`를 실행한다.

### 에디터 사용 순서

1. **SSH에서 불러오기…**를 누른다.
2. 기존 SSH 호스트를 고르고 **폴더 열기**를 누른다. 처음에는 원격 홈(`~`)을 연다.
3. 폴더를 눌러 이동하거나 데이터 폴더 경로를 한 번 입력한다. 개별 파일 경로를 입력할 필요는 없다.
4. 원격 `.bag`을 체크한다. 다른 폴더로 이동해도 같은 호스트의 선택은 유지된다.
5. **선택한 N개 다운로드·가져오기**를 누른다.
6. 작업 목록에서 다운로드 MiB/전체 MiB와 순차 import 상태를 확인한다.
7. 완료된 원본을 **현재 프로젝트에 추가**한다. 일부만 성공했다면 성공한 원본부터 추가할 수 있다.

녹화 중인 `.bag.active`는 표시하지 않는다. `.bag`이라도 전송 중 크기/수정 시각이 바뀌면
완료본으로 취급하지 않는다. 수집 종료 후 다시 선택한다. 현재 SSH 기능은 **bag 파일용**이며,
원격 LeRobot 폴더 전체를 내려받는 기능은 포함하지 않는다.

## 중단·실패 후 이어가기

작업의 **작업 취소**는 다음 전송/처리 단위에서 반영된다. 이미 완료된 원본과 미완료
다운로드를 지우지 않는다. 앱 창만 닫는 것은 취소가 아니며 worker는 계속 실행된다.

실패 또는 취소된 여러 파일 작업에서 **중단·실패한 파일 이어가기**를 누르면:

- 이미 import가 끝난 원본은 건너뛴다. 해당 원본은 이전 작업의 추가 버튼을 사용한다.
- 다운로드 중이던 파일은 남은 `.partial`에서 이어받는다. 기존 부분의 SHA-256을 원격과 비교한다.
- 다운로드가 끝난 파일은 로컬 cache를 재사용한다. 완료된 전체 파일을 다시 전송하지 않는다.
- 새 작업으로 나머지를 처리하므로 이전 작업의 결과/로그는 남아 있다.

완료 작업에서 같은 파일을 새로 선택해 다시 가져오면 다운로드는 재사용할 수 있지만
별도 import 원본이 만들어질 수 있다. 기존에 추가한 원본을 무조건 중복 추가하지 않도록 확인한다.

## 저장 위치·원본 보존·제한

- 받은 bag: `workspace/downloads/<파일 버전 식별자>/<원래파일명>.bag`
- 미완료: 같은 폴더의 `download.partial`; 완료 시에만 `.bag`으로 반영한다.
- 전송 검증: SHA-256으로 이어받은 부분과 완료 파일을 확인한다.
- 버전 구분: Host 별칭·원격 절대 경로·크기·mtime으로 cache를 구분하므로, 새 버전이 기존 프로젝트 원본을 덮어쓰지 않는다.
- 빠른 재사용은 원격 size/mtime 및 로컬 size/mtime 기록으로 판정한다. 외부에서 내용을 바꾼 뒤
  크기/mtime까지 원래대로 복원한 변경은 감지하지 못한다. cache 파일은 직접 수정하지 않는다.
- 원격에는 폴더 조회·stat·파일 읽기만 수행한다. 원격 원본의 수정·삭제·이동 명령은 없다.
- SSH 비밀번호·개인 키·SSH 설정 내용은 프로젝트/Git에 저장하지 않는다. 작업/다운로드 기록에는
  재시도에 필요한 Host 별칭과 원격 경로가 남으므로 workspace는 개인 작업 데이터로 관리한다.
- import cache와 다운로드 원본이 모두 필요해 로컬 디스크 사용량이 늘어난다. 자동 삭제하지 않는다.
- 강제 종료로 lock이 남았으면 PID와 작업 상태를 확인한 후 복구한다. 실행 중인 작업의 lock을 지우지 않는다.
- 에디터 API는 SSH 접근 기능도 있으므로 인증 없이 외부 IP에 공개하지 않는다. 원격 UI 접속은 SSH 터널을 쓴다.

현재 검증은 합성 bag과 로컬 read-only transport로 수행했다. 실제 robot-up 같은 개인 호스트의
키 인증·네트워크 경로는 사용 환경에서 첫 연결 시 확인해야 한다.

공식 참고: [OpenSSH ssh](https://man.openbsd.org/ssh.1), [SSH 설정](https://man.openbsd.org/ssh_config.5).
